# v0.3 authoring and overlap audit

This note records the semantic review that is intentionally outside the
structural YAML validator. Version 0.3.0 contains 38 public and 12 held-out
scenarios after the six local held-out v0.2 items are present.

## v0.2 proof corrections

- **Presence:** a flap is a drop plus a reconnect. At 2M users and 30
  flaps/hour, that is about 33.3K transitions/s. Six active viewers produce
  about 200K presence deliveries/s; message fan-out adds about 60K/s, so
  interest management alone exceeds the 200K/s fleet cap. The prompt now
  states that 80% reconnect within eight seconds. An eight-second grace stays
  inside the ten-second visibility bound and reduces presence to about 40K/s,
  making debouncing independently necessary.
- **Session revocation:** healthy feed delivery now has a hard 45-second
  maximum rather than only a percentile. Three missed five-second heartbeats
  make a gateway stale. Because the request-path limit is an unconditional
  five milliseconds and central validation takes 20-80 milliseconds, the
  stated constraints entail rejecting at a stale gateway; the previous
  central-fallback gold violated its own latency constraint.
- **Time-series engine:** the prompt now supplies measured random/sequential
  I/O bounds, compression ratios, a cold-storage cap, an erasure-rewrite cap,
  and explicit regulatory acceptance of audited key destruction. These facts
  make LSM, columnar segments, and crypto-shredding consequences of arithmetic
  rather than taste.

## Haystack rendering discipline

`prompt.py` deliberately renders every numbered constraint and requirement;
the `implicit` and `stated_in_prompt` flags are metadata, not redaction. Long
items therefore keep exact needles only in the source document prose. Their
numbered constraints and requirements use umbrella language that points back
to the document without repeating the operative clause. No additional
haystack siblings are added in v0.3.

## Distinct-gold review

| Potential overlap | Distinguishing scored reasoning |
|---|---|
| Time-series erasure / event-lake erasure | TSDB scores engine I/O structure, compression, retention, and key deletion. The lake item scores erasure propagation through immutable raw events, manifests, derived views, and subject-key lineage. |
| Retail lookup infeasibility / residency conflict | Retail is a propagation-latency and linearizable-cache impossibility. Residency is a legal process-location contradiction; faster networks and caches do not change where computation is legally permitted. |
| Quoting or mine stale data / cold-chain alarming | Existing items react to observed gaps or stale facts. Cold-chain scores the absence of an expected heartbeat as the alarm event, including deadline and false-negative math. |
| Ticket allocation / omnichannel inventory | Ticketing scores fixed-capacity spike admission and strong allocation. Omnichannel scores different availability/consistency policies across disconnected POS and online reservations, followed by compensation. |
| Mine failure policy / dual rate limiter | Mine routing applies fail-closed behavior to a safety fact under disconnection. The rate limiter derives opposite failure policies for abuse and billable flows from their different economic failure costs. |
| Metering short / metering haystack | This is an intentional extraction minimal pair with identical gold. It contributes one architectural item and one controlled document-load measurement, not two independent design claims. |
| Delivery-promise feasible / last-mile infeasible | This is intentional arithmetic symmetry. The same route model lands just inside versus just outside the window, punishing both reflexive infeasibility and reflexive design. |

## v0.3 coverage axes

The 20 v0.3 items each have a primary axis not present in v0.1/v0.2:

- dependency-closed transitions, lease fencing, retry multiplication, quorum
  reconfiguration, and consistent distributed cuts;
- bitemporal genealogy, tombstone resurrection, semantic event replay, and
  security/privacy clarification;
- recovery trust cycles, ambiguous irreversible effects, atomic cross-shard
  metadata, and content-addressed garbage collection;
- repair-controller feedback, trace-tail sampling, point-in-time ML joins,
  topology-aware gang scheduling, contact-plan routing, and fan-out percentile
  multiplication.

## Mechanical acceptance

Before release:

1. Parse and validate all 50 YAML files.
2. Assert every declared flow slot has a `slot_match` gold item.
3. For each infeasible item, document why removing any member of the expected
   conflict set restores a feasible path.
4. Run the full unit suite.
5. Pilot public scenarios with an explicit `--scenarios scenarios/public` path;
   the generic CLI default also sees local held-out files.
6. Record model/item pass patterns separately from semantic authoring changes;
   never weaken a proved item merely because every model misses it.
